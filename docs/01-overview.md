# 01. 概要

## 目的

複数のAIコーディングエージェントに対し、危険・不適切な操作を **エージェント横断で同一に** ブロックするガードレールを提供する。

## スコープ

### 対応エージェント

| エージェント | Hook機構 | 状態 |
| --- | --- | --- |
| Claude Code | `PreToolUse` Hook | 対応 |
| Cursor | `beforeShellExecution` / `beforeReadFile` Hooks | 対応（書き込みに制約あり。[05-agent-cursor.md](05-agent-cursor.md) 参照） |

将来的に他エージェント（例: Aider, Cline 等）を追加する場合も、**共通判定エンジンは再利用し、アダプタのみを追加** する方針とする。

### ガードレールが防ぐ操作（初期要件）

1. **機密ファイルの読み書き禁止**
   `.env` 等、機密情報を含みうる特定ファイルへの read / write を禁止する。
2. **リモートコードの直接実行禁止**
   `curl`/`wget` で取得した内容をパイプ等でシェルに直接渡す実行を禁止する。
3. **危険な `rm` の禁止**
   ユーザーディレクトリ（`$HOME`）以下以外での、ワイルドカードを含む `rm` を禁止する。
4. **Docker/Podman の CLI ボリュームマウント禁止**
   `docker run -v ...` 等、CLI 上での `-v` / `--volume` / `--mount` 指定を禁止する。
   正当なマウントは `docker-compose.yaml` 等に定義する運用を想定する。

追加で検討すべきガードレールは [08-additional-guardrails.md](08-additional-guardrails.md) に記載する。

## 基本方針

- **ルールはデータ、ロジックは共通**:
  禁止対象は `rules/*.json` に定義し、判定ロジック（`core/`）は1つだけ持つ。
  これにより「全エージェントで同じ要件を満たす」を構造的に保証する。
- **追記で拡張可能**:
  新しい禁止対象は原則 `rules/*.json` への追記のみで対応完了とする。
  正規表現で表現できない複雑な判定のみ、`core/` に `builtin` 評価関数を追加する。
- **言語は Bash を基本**:
  Hook スクリプトは各エージェントが直接起動するため、依存の少ない Bash を基本とする。
  JSON の解析には `jq` を用いる。Bash で表現困難な処理が出た場合のみ他言語を検討する。
- **fail-safe の方針を明確化**:
  ルール評価で「該当した」場合のみ deny する（デフォルト allow）。
  ただしアダプタ／エンジンが異常終了した場合の挙動は各エージェント設定で `failClosed` 相当を選べるようにする（[02-architecture.md](02-architecture.md) 参照）。
- **テスト必須**:
  `core/` の判定ロジックおよび各アダプタには必ずテストコードを用意する（[07-testing.md](07-testing.md)）。
- **実行環境は Docker**:
  テスト・動作確認は Docker 上で行い、`docker-compose.yaml` でローカル確認できるようにする。

## 用語

| 用語 | 意味 |
| --- | --- |
| Hook | エージェントがツール実行前後に外部スクリプトを呼び出す仕組み |
| アダプタ | 各エージェントのHook入出力フォーマットと、共通エンジンの標準フォーマットを相互変換するスクリプト |
| 共通判定エンジン | エージェント非依存で、標準判定リクエストを受けてルールを評価し標準判定結果を返す `core/guardrail.sh` |
| 標準判定リクエスト | エージェント差を吸収した内部共通の入力JSON（`operation`/`path`/`command` 等） |
| 標準判定結果 | 内部共通の出力JSON（`decision`/`rule_id`/`message`） |
| ルール | `rules/*.json` 内の1つの禁止定義 |
